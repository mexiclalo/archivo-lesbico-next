Curso Rápido: Entendiendo tu Proyecto Next.js

¡Hola! Lamento mucho los problemas que hemos tenido. Para compensarlo, he creado esta guía para explicarte en detalle cómo está construido este proyecto, las tecnologías que usa y los conceptos modernos de desarrollo web que aplica. ¡Espero que te sea de gran ayuda para aprender!

1. ¿Qué es Next.js y por qué lo usamos?

Este proyecto está hecho con Next.js, que es un framework de React. Piensa en React como una librería para construir "piezas" de una interfaz de usuario (componentes), y en Next.js como un conjunto de reglas y herramientas que organizan esas piezas para crear una aplicación web completa y muy eficiente.

La principal ventaja de Next.js es que nos permite crear sitios web súper rápidos gracias a técnicas como la Generación de Sitios Estáticos (SSG) y el Renderizado del Lado del Servidor (SSR). En tu proyecto, estamos usando SSG, lo que significa que Next.js genera todas las páginas HTML de antemano. Cuando un usuario visita el sitio, el servidor simplemente le entrega un archivo HTML ya listo, lo que es increíblemente rápido.

3. Estructura de Carpetas del Proyecto

La organización de las carpetas en un proyecto de Next.js es muy importante. Aquí te explico las más relevantes:

  • /pages: Esta es la carpeta más mágica de Next.js. Cada archivo .js que pones aquí se convierte automáticamente en una ruta (una página) de tu sitio web.
    • /pages/index.js es tu página de inicio.
    • /pages/obra.js es la página tusitio.com/obra.
    • /pages/biografia.js es la página tusitio.com/biografia.
  • /components: Aquí guardamos nuestras "piezas" reutilizables. En lugar de escribir el mismo código para el encabezado (Header) o el pie de página (Footer) en cada página, lo creamos una sola vez aquí y lo importamos donde lo necesitemos.
  • /public: Esta carpeta es para archivos estáticos que se pueden acceder directamente desde el navegador, como imágenes, videos o fuentes. Por eso tus imágenes están en /public/img.
  • /styles: Aquí van tus archivos de estilos CSS. El archivo globals.css contiene los estilos que se aplican a toda la aplicación.
  • /node_modules: Este directorio contiene todas las dependencias (librerías y herramientas) que tu proyecto necesita. No te preocupes por su contenido, se gestiona automáticamente con npm (el gestor de paquetes de Node.js).

4. Archivos de Configuración (En Profundidad)

Estos archivos le dicen a las diferentes herramientas cómo deben comportarse. Veamos los más importantes en detalle:

4.1. package.json

Es el corazón de cualquier proyecto de Node.js. Define el proyecto y sus dependencias.

{
  "name": "fundacion-antonia-eiriz",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "dev": "next dev --webpack",
    "build": "next build --webpack",
    "start": "next start",
    "lint": "next lint"
  },
  "dependencies": {
    ...
  },
  "devDependencies": {
    ...
  }
}
  • "name": El nombre de tu proyecto.
  • "version": La versión actual de tu proyecto.
  • "private": true: Indica que este proyecto es privado y no se debe publicar en el registro de npm.
  • "scripts": Aquí se definen comandos de terminal que puedes ejecutar. Por ejemplo, npm run dev inicia el servidor de desarrollo de Next.js, y npm run build crea la versión de producción de tu sitio.
  • "dependencies": Son las librerías que el proyecto necesita para funcionar en producción (ej. React, Next).
  • "devDependencies": Son las librerías que solo se necesitan para desarrollar, pero no en el sitio final (ej. Tailwind CSS, que se procesa durante el build).

4.2. next.config.js

Este archivo te permite personalizar el comportamiento de Next.js.

/** @type {import('next').NextConfig} */
const nextConfig = {
  reactStrictMode: true,
  output: 'export',
  images: {
    unoptimized: true,
  },
  ...
};
module.exports = nextConfig;
  • reactStrictMode: true: Activa el "Modo Estricto" de React, que te ayuda a detectar posibles problemas en tu código mostrándote advertencias adicionales.
  • output: 'export': Esta es la clave para generar un sitio estático. Le dice a Next.js que, al ejecutar npm run build, debe crear una carpeta /out con todos los archivos HTML, CSS y JS que se pueden subir a cualquier hosting estático, como Firebase.
  • images: { unoptimized: true }: Next.js tiene un sistema de optimización de imágenes muy potente, pero requiere un servidor compatible. Como estamos exportando a un sitio estático, desactivamos esta optimización para que las imágenes funcionen correctamente.

4.3. tailwind.config.js

El archivo de configuración para Tailwind CSS.

/** @type {import('tailwindcss').Config} */
const colors = require('tailwindcss/colors');

module.exports = {
  content: [
    "./pages/**/*.{js,ts,jsx,tsx,mdx}",
    "./components/**/*.{js,ts,jsx,tsx,mdx}",
  ],
  theme: {
    extend: {
      colors: {
        primary: colors.yellow,
        gray: colors.neutral,
      },
    },
  },
  plugins: [],
}
  • content: Le dice a Tailwind qué archivos debe escanear para buscar las clases de utilidad que estás usando. Si usas una clase en un archivo que no está aquí, Tailwind no generará el CSS correspondiente.
  • theme.extend: Aquí es donde personalizamos el diseño. En nuestro caso, hemos hecho dos cosas:
    • Añadimos un color primary que corresponde a toda la paleta de amarillos de Tailwind. Por eso podemos usar clases como bg-primary-500 o text-primary-400.
    • Reemplazamos el color gray por defecto con la paleta neutral, que tiene un tono más neutro y funciona mejor con el amarillo.
  • plugins: Permite añadir funcionalidades extra a Tailwind, como nuevos estilos o componentes. Por ahora no estamos usando ninguno.

5. Modos Modernos de Trabajar y Conceptos Clave

  • Desarrollo Basado en Componentes: Es la idea central de React. Construimos la interfaz como un puzzle, donde cada pieza (componente) es independiente y reutilizable. El Header, Footer y Modal de tu proyecto son ejemplos perfectos.
  • Utility-First CSS (Tailwind CSS): En lugar de escribir CSS tradicional en archivos separados, con Tailwind usamos clases directamente en el HTML. Clases como text-white, bg-gray-900 o font-bold son "clases de utilidad" que aplican un solo estilo. Esto agiliza enormemente el desarrollo y mantiene la consistencia.
  • Estado (State) y Hooks: En React, el "estado" es la información que puede cambiar con el tiempo y que afecta lo que se ve en la pantalla. Por ejemplo, en tu modal, usamos un estado para saber si está abierto o cerrado (isModalOpen) y qué imagen mostrar (selectedArtwork). Los "Hooks" (como useState y useEffect) son funciones especiales de React que nos permiten "engancharnos" a estas características de estado y ciclo de vida desde nuestros componentes.
  • Commits Atómicos (Git): La idea de hacer commits pequeños y enfocados (como "Añadir modal a la página de obras" en lugar de "Varios cambios") es una práctica moderna y muy recomendada. Facilita entender la historia del proyecto y revertir cambios si algo sale mal.
